# RN 0.88.0 升级与覆盖证据

本记录对应 `upgrade/rn88-full-coverage-20261016`，起点为
`d52172a2827f2d8d2ca84fbd641c75ae3b423175`。包版本仍为 `1.6.2`；本轮没有提交、推送或发布。

## 实际开发与消费基线

根工程、持久 example 和文档站实际安装 React Native `0.88.0`、React `19.3.0`、
Reanimated `4.7.1`、Worklets `0.13.0`、SVG `15.16.0` 与 Icons `0.4.1`。
根 peer 保留已有兼容范围，没有用扩大 peer 代替实际升级。Yarn `4.11.0` 锁文件随安装更新。

RN/Metro `0.88.0` 实际要求 Node `^22.13.0 || ^24.3.0 || >= 26.0.0`。
根 `devEngines` 与私有 example/website 的 `engines` 对齐该范围，CI 和开发使用已有
`.nvmrc` 的 `24.13.0`；公开库 `engines` 保留已有 RN `0.86+` 消费者范围，不把它当作
当前开发工具链范围。官方 template 的 `>=22.11.0` 与 RN 包自身要求不一致，未沿用该旧声明。

原生 example 按 npm integrity 已校验的正式 `@react-native-community/template@0.88.0`
对齐，保留应用标识和业务资源。Android 使用 Gradle `9.4.1`、Kotlin `2.2.0`、
compile/build tools 37、target 36；iOS 使用正式模板的 AppDelegate/SceneDelegate 生命周期。
临时 runtime harness 的模板、CLI、版本核对脚本及说明同步升级。

文档站显式消费 `react-native-web@0.21.4` 和 `@react-native/assets-registry@0.88.0`。
RNW 0.21.4 的正式发布包含公开 `AssetRegistry` 导出及 CJS/ESM 共享注册表，见
[上游发布记录](https://github.com/necolas/react-native-web/releases/tag/0.21.4)。
SVG 的 Web 资产依赖按[官方配置](https://github.com/software-mansion/react-native-svg/blob/main/USAGE.md#web-configuration)
显式安装。仅对该 registry 包应用 Babel CommonJS 转换，以处理它同时使用 ES import 和
`module.exports` 的源码；没有私有模块 alias 或 node_modules 补丁。

## JS/TS 覆盖范围与结果

（48 suites、416 tests，9 个 governed owner suites selected/completed 均通过），
随后运行完整覆盖（102 suites、1098 tests），两阶段全部通过。
`yarn test:coverage --maxWorkers=2` 仍提供直接执行完整覆盖的入口。
覆盖所有 `src/**/*.{js,ts,tsx}` 和 `example/src/**/*.{js,ts,tsx}`，仅排除 example 测试自身；
包括 `.web` 实现、异步 owner/store、异常输入和宿主生命周期。没有新增 ignore 或缩小既有 example 分母。

## 自有原生代码

本库没有自有原生模块实现；需要覆盖的原生源码是 example 的两份 Swift 和两份 Kotlin 宿主文件。
runner 直接编译原文件，校验全部源码清单，并把文件 SHA-256 与报告记录在 `scope.json` 中。
SDK 边界使用受控替身，Swift Foundation/Bundle 使用真实实现。该覆盖不等于 SDK 内部覆盖或真机验收。

## 生产源码的最小修正与不可达证明

以下删减逐项基于实际控制流和运行时不变量，不是因为类型声明或测试难度认定不可达。
相应正常输入、无效输入及生命周期测试仍保留并补充。

| 文件/位置                          | 前置事实与修改                                                                                                                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `imageSource` undefined 分支       | 函数入口已处理 undefined，switch 内重复分支不可达。                                                                                                                         |
| `imageSource` array length         | Array 的 length 不可配置；隐藏 length 的 Proxy 会在 `Reflect.ownKeys` 抛错并由现有异常路径接住，因此后续缺键分支不可达。                                                    |
| `imageSource` 外层 catch           | 对象反射均在 visit 自有 try/catch 内，原始值路径不执行用户代码；移除重复外层 catch，保留 Proxy/getter 异常测试。                                                            |
| `NavBar/isSlot`                    | 非对象已在前面退出；thenable 私有函数只在对象路径调用。Promise executor 同步完成回调赋值，移除永不调用的初始空函数。                                                        |
| `GradientWash`                     | 四段 dense split 已证明第四段存在；hex 正则通过后固定位置字符存在，直接按位置读取，保留所有合法色型和非法值测试。                                                           |

| `PulseDot`、两端 `ToastHost` props | React 对无属性 JSX 也传入 props 对象；删除函数整参默认值，保留真实 `<Component />` 测试。直接把函数组件当普通函数调用不属于其公开契约。                                     |

| 两端 `ToastHost` 清除状态          | 每次 delivery 状态更新前同步写 identity；identity 和 store CAS 校验通过时不能存在替换投递。完成动作无可重入订阅回调，删除重复 updater 比较，同 tick 替换/过期退出测试保留。 |
| `ConfirmHost` 清除状态             | pending ref 同步标识每次投递；已匹配 event id 后清空 ref，再按相同队列顺序清状态。过期 clear 和新 show 测试保留。                                                           |
| Toast `popSuspended`               | 只压入成功挂起的 live owner；失败者不入栈，release 在清 subscriber 前移出栈，故不需要弹出时再过滤。Confirm 的不同栈语义仍保留原过滤。                                       |
| `ScreenBackdrop`                   | 私有 helper 只有两个调用，均传入模块初始化时的固定四 stop 色板和四个 offset；移除不存在的 offset fallback。                                                                 |

另有两类实际修正：

- `NavigationScene` 的 `in` 错把 `__proto__` 等继承属性识别成合法选项。先由回归测试复现，再改为 `Object.hasOwn`；三个静态 label record 自有值均是非空字符串，随后多余 fallback 同步移除。
- `AvatarWithRing/styles` 给工厂返回值明确公开 RN style 类型，避免 RN 0.88 的声明生成泄漏不可命名私有类型；运行行为不变，Bob 声明构建和公开入口消费者测试通过。

工具 fixture 的子进程输出上限改为 16 MiB，清理加入有限重试，并明确检查 spawn error。
原因是完整负向契约执行超过默认 1 MiB 缓冲，子进程被杀且清理掩盖原错误；没有跳过或减少契约用例。
